# GOAL Card — [STORE-01] 초등 저학년 칭찬스티커 보드판 세트 출시

> CLAUDE.md §H GOAL 카드 시스템의 첫 인스턴스. Store OS의 기본 첫 슬라이스를 정식 GOAL 형식으로 정의.

## 목표

초등 1–3학년 자녀를 둔 학부모를 타겟으로 한 **칭찬스티커 보드판 + 칭찬스티커 세트**를 네이버 스마트스토어에 출시하여 **Mini 단계 졸업 조건**(실 판매 10건 + 긍정 리뷰 3건 + 순이익 > 0)을 확보한다.

## 범위

### 포함
- 칭찬스티커 보드판 1종 (A4 또는 A3 사이즈, 자녀 이름 커스터마이즈 옵션)
- 칭찬스티커 세트 1종 (보드판과 매칭되는 디자인)
- 네이버 스마트스토어 1채널 입점·운영
- 자가 인쇄 또는 인쇄 대행 (Mini는 운영자 직접 발주)
- **Claude Design** 기반 자산 생성 (AI 디자인 → 운영자 검토·승인 → DesignAsset 레코드)
- Claude (웹 인터페이스 또는 API) 사용한 상품 설명 1회 생성

### 제외 (다른 GOAL로 분리)
- 다채널 동시 입점 (쿠팡·Shopify) → [STORE-02]에서 검증 후 추가
- FastAPI 자체 주문 시스템 → Mini 졸업 후 [STORE-04] Standard 진입 시
- 자동 CS 응답·이미지 자동 생성 → Standard 이상
- 캐릭터·연예인·디즈니 등 IP 사용 → [STORE-10] precheck 통과 전 일체 금지
- 학습 효과 보장·성적 향상 같은 단정적 표현 일체 금지

### 단계

**Mini** — 시스템 개발 0줄. 출시까지 2주 목표.

## Observations (현재 상태·근거)

- 시장: 네이버쇼핑 "칭찬스티커" 키워드 검색 시 80+ 상품 노출. 가격대 5,000–25,000원. 중·고가는 캐릭터 라이선스 제품, 저가는 일반 디자인.
- 우리 차별점 후보: **자녀 이름 커스터마이즈 + 부모 친화적 칭찬 문구** (단순 "잘했어요" 대신 행동 기반 — "스스로 정리했어요", "약속 지켰어요" 등).
- 운영자 역량: 디자인 도구 직접 작업 부담 ↓ (Claude Design 활용), 코딩 초보, 한국어 모국어, 네이버 스마트스토어 입점 경험 0.
- 자본: 초기 입점·디자인 도구는 무료. 인쇄·재고 발주 첫 라운드 10–30만원.
- 법률 확인 사항: 사업자등록·통신판매업 신고 (필수, 무료, 2주 내), 약관·환불 정책 작성.

## Alternatives (검토한 접근법)

### A. Claude Design + 인쇄소 발주 + 네이버 입점 (Recommended)
- 장점: 가장 빠른 출시 (2주), AI 디자인 속도·일관성, 운영자 디자인 작업 부담 ↓, DesignAsset 버전 관리·proof 게이트 강제.
- 단점: AI 출력 품질 변동성 → 여러 번 iteration 필요할 수 있음, IP precheck 의무, 첫 출력 prompt 작성 학습 곡선.

### B. 외주 디자인 + 인쇄 대행 + 네이버 입점
- 장점: 디자인·품질 수준 ↑.
- 단점: 출시 4주+ 지연, 디자인 발주 30–50만원, 외주 의존 리스크. Mini 단계 검증 비용으로 과함.

### C. Shopify·자체 사이트 우선
- 장점: 브랜드 통제, 다채널 확장 용이.
- 단점: Mini 졸업 조건은 "10건 실 판매" — 트래픽 0 상태의 자체 사이트로는 거의 불가능. 네이버 스마트스토어가 가진 검색·신뢰 자산을 활용 못함.

## Logic (왜 A인가)

Mini 단계의 목적은 **수요 검증**. 디자인 완성도·브랜드 통제는 Standard/Full에서 키울 일. Mini는 "이 제품을 모르는 사람이 검색하고 구매하는가"를 검증하는 단계이고, 네이버 스마트스토어가 검색·결제·배송·CS 채널을 다 깔아두었으므로 **추가 인프라 0줄로 검증 가능**. 디자인은 Claude Design으로 충분 (베스트셀러 중 단순 디자인 다수 — AI 출력 + 운영자 검수로 품질 확보 가능). 운영자 디자인 도구 학습 부담 ↓ + DesignAsset proof 게이트로 IP·과대광고 리스크 자동 차단. 인쇄는 외부 인쇄소 — 첫 50건은 단가가 아니라 데이터가 목적.

## Risks (식별 + 완화)

| 리스크 | 영향 | 완화 |
|---|---|---|
| 어린이 대상 과대광고 (학습 효과·성적 향상 보장) | 공정거래법 위반, 행정처분 | `legal_check.py` 통과 필수. "학습 습관 형성 도구"·"활용 가능"으로만 표현 |
| IP 침해 (캐릭터·일러스트 무단 사용) | 손해배상·삭제명령 | 캐릭터·연예인·디즈니 일체 사용 금지. 직접 디자인 또는 무료 상업 이용 가능 자산만 |
| 사업자 정보 미표시 | 전자상거래법 제10조 위반 | 사업자등록·통신판매업 신고 완료 후 상품 등록. 상세페이지에 상호·대표자·번호·주소·연락처 표시 |
| 환불 정책 모호 | 분쟁 시 운영자 불리 | "7일 이내 반품 가능, 단 개봉 시 제외" 정책 명시. 약관 별도 페이지 |
| 인쇄 품질 불만족 → 환불·악평 | 졸업 조건의 "긍정 리뷰 3건" 차단 | 첫 10건은 무작위 1건 운영자가 직접 받아 품질 자가 검증 후 본격 판매 |
| L0 자동화 충돌 | 결제·환불·계좌·법률 문구를 AI가 처리 | Mini는 자동화 0. Claude는 상품 설명 초안만 — 운영자가 편집·승인 후 등록 |
| 시크릿 노출 | API 키·계좌 정보가 prompt·소스에 들어감 | Mini는 Claude API 자체 미사용 가능 (웹 인터페이스로 충분). 사용 시 환경변수 |
| 개인정보 과수집 | PIPA 위반 | 네이버 스마트스토어 기본 수집 항목만 사용. 별도 DB 구축 X |

## Decision Needed (운영자가 결정해야 할 사항)

1. **사업자등록 진행 여부 + 시점** — 2주 출시 일정의 critical path. 미진행 시 출시 자체 불가.
2. **자가 인쇄 vs 동네 인쇄소** — 단가·품질·납기 trade-off. 운영자 직접 판단.
3. **첫 라운드 수량** — 10건 / 30건 / 50건 중 어디? (제안: 검증 단계이므로 **30건**, 졸업 조건 10건 + 운영자 직접 검수용 1건 + 여유 19건)
4. **가격대** — 9,900원 (보드판+스티커 세트, 부담 적은 가격) vs 14,900원 (프리미엄 포지셔닝). 제안: **9,900원** Mini 검증용.
5. **자녀 이름 커스터마이즈 가격** — 무료 vs +2,000원. 제안: **무료** (차별화 무기로 사용).
6. **인쇄 발주 후 재고 보관 위치** — 운영자 자택? 별도 보관?
7. **CS 응답 채널** — 네이버 톡톡? 이메일? 응답 SLA?

## Evidence Required (Mini 졸업을 위한 증거)

| 항목 | 측정 방법 | 목표 |
|---|---|---|
| 실 판매 건수 | 네이버 스마트스토어 통계 (지인 제외 식별) | **10건+** |
| 긍정 리뷰 | 네이버 리뷰 페이지 (4점 이상) | **3건+** |
| 재구매 또는 문의 | 톡톡 또는 동일 고객 재주문 | **1건+** |
| 순이익 | 매출 − (인쇄·재료·배송·수수료) | **> 0** |
| 법률 점검 통과 | `python scripts/legal_check.py listings/store-01.md` | 필수 조치 0건 |
| 운영자 자가 품질 검수 | 첫 1건 운영자 직접 수령 후 사진 + 메모 | 통과 |
| audit log | 상품 등록·가격 변경·CS 응답 기록 | 모든 운영 행동 기록 |

위 7개를 모두 충족하면 [STORE-04] Mini → Standard 졸업 GOAL로 전환.

## Automation Boundary Map (L0–L3)

| 작업 | 레벨 | 이번 GOAL 처리 |
|---|---|---|
| 사업자등록 신청 | L0 | 운영자 직접 (자동화 영구 금지) |
| 통신판매업 신고 | L0 | 운영자 직접 |
| 약관·환불 정책 작성 승인 | L0 | AI 초안 → 운영자 검토·승인 |
| 상품 디자인 (Claude Design) | L1 | AI 자산 생성 → 운영자 검토·승인. DesignAsset 레코드 + proof_status 의무 |
| 상품 설명 카피 | L1 | Claude 초안 → 운영자 편집 → `legal_check.py` 통과 → 등록 |
| 가격·재고 설정 | L1 | 운영자 직접 |
| 네이버 스마트스토어 상품 등록 | L1 | 운영자 직접 클릭 (Mini는 API 미사용) |
| CS 응답 | L1 | 운영자 직접 (Mini는 자동화 X) |
| 인쇄 발주 | L0 | 운영자 직접 (금액·품질 책임) |
| 발송 | L0 | 운영자 직접 |
| 환불 결정 | L0 | 운영자 직접 |

**이번 GOAL에는 L2·L3 자동화 일체 없음.** Standard 진입 후 시작.
